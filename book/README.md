## writing the book

the book is tested like code (`cli/tests/book.rs`), in one workspace with
the clock frozen:

- a ```` ```xmd name.x.md ```` block is a file later blocks and chapters
  can import or query; ```` ```xmd ```` alone is a note of its own. every
  block must have no diagnostics
- each line of a ```` ```bash ```` block that runs `xmd` is run as
  written. `#=> text` after a command is what it has to print
- `snapshots/` holds what every block renders and every command prints

never type a result by hand: put it in a block and let the snapshot show
it. a change to the language that changes the book fails `cargo test`;
rerun with `UPDATE_SNAPSHOTS=1` and commit the chapter and its snapshot
together

the site build (`client/web/scripts/lib/book.mjs`) turns these pages into
`dist/book/` and fails on a link to nothing. `client/web/tests/book.spec.mjs`
checks that the browser renders every block the way the snapshots record

`reference/` is generated by `cli/tests/reference.rs` from the built-in
table, the stdlib libraries, the query collections, and the contract
between native code and the modules (the stdlib functions it calls, the
hooks and the `step` loops); never edit it by hand. a library export
needs a `//` comment above it, which becomes its description.
`UPDATE_SNAPSHOTS=1` regenerates it too
